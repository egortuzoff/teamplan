# TeamPlan

Веб-приложение для учёта расписания, явки, составов и результатов спортивной команды.
Учебный проект. **Этап 1**: вход, список игроков, события, явка на тренировки и сборы, состав на игру.

Документы проекта: бизнес-постановка TP-BP-001 (версия 0.9) и ТЗ TP-TZ-001 (версия 0.1).

## Что умеет приложение (этап 1)

- Вход по логину и паролю. Аккаунты и пароли создаёт организатор, игрок пароль сам не меняет.
- Организатор ведёт список игроков, создаёт, редактирует, отменяет и удаляет события трёх типов: тренировка, сбор, игра.
- Явка («буду», «под вопросом», «не буду») отмечается только на тренировки и сборы. Игрок отмечает себя, организатор любого игрока. После начала события отметки не меняются. Есть сводка и подсветка не ответивших после срока «ответить до».
- На игры явка не отмечается. Организатор выбирает состав из всех игроков, сохраняет черновик и публикует. Игрок видит только опубликованный состав, до публикации там надпись «Состав пока не объявлен».
- Отмена оставляет событие в расписании с пометкой «отменено». Удаление убирает событие, отметки и состав.

**Не входит в этап 1** (будет на этапе 2): результат игры, голы и передачи, статистика игроков, лента уведомлений. В коде эти места помечены комментариями `TODO этап 2`.

## Требования

- Windows, Python 3.12 или новее (с python.org, при установке отметьте «Add python.exe to PATH»).
- Браузер Chrome, Firefox или Edge.
- Интернет нужен только для установки зависимостей.

## Установка и запуск (Windows, PowerShell)

Все команды выполняются в папке проекта (в Проводнике откройте папку, в адресной строке введите `powershell` и нажмите Enter).

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python seed.py
streamlit run app.py
```

Если команда `python` не найдена, используйте `py` вместо `python`.
Если PowerShell пишет, что выполнение скриптов отключено, выполните
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` и повторите активацию.
Если Streamlit при первом запуске спрашивает e-mail, просто нажмите Enter.

Приложение откроется в браузере по адресу http://localhost:8501. Остановить: `Ctrl+C` в PowerShell.
Следующий запуск: активировать окружение и выполнить `streamlit run app.py` (команду `seed.py` повторять не нужно).

## Тестовые аккаунты (вымышленные)

| Роль | Логин | Пароль |
|---|---|---|
| Организатор | trener | trener-demo-1 |
| Игрок | igrok1 | igrok1-demo |
| Игрок | igrok2 | igrok2-demo |
| Игрок | igrok3 | igrok3-demo |

`seed.py` создаёт также тренировку, выездной сбор и игру с опубликованным составом из двух игроков (даты считаются от дня запуска).
Чтобы начать с чистой базы: `python seed.py --reset`.
Для реальной работы без тестовых данных: `python create_organizer.py` создаёт только аккаунт организатора.

## Тесты

```powershell
python -m pytest
```

Тесты проверяют правила из ТЗ: даты и названия событий, уникальность логина, права игрока и организатора, явку после начала события, видимость черновика и опубликованного состава, удаление событий и откат при сбое записи.

## Как проверить вручную

1. Войдите как `trener`: видны разделы «Расписание», «Новое событие», «Игроки».
2. Откройте тренировку: есть явка и сводка. Откройте игру: есть состав, явки нет.
3. Создайте игру, выберите состав, сохраните как черновик. Выйдите, войдите как `igrok1`: состав не виден («Состав пока не объявлен»). Войдите как `trener`, опубликуйте, снова как `igrok1`: состав виден.
4. Как `igrok1` отметьте явку на тренировку. Разделов «Новое событие» и «Игроки» у игрока нет.
5. Отмените событие: оно остаётся в списке с пометкой. Удалите событие: исчезает из списка.
6. Остановите приложение (`Ctrl+C`) и запустите снова: данные на месте.

## Структура проекта

```
app.py               экраны (Streamlit)
seed.py              тестовые данные
create_organizer.py  создание аккаунта организатора
teamplan/            логика и правила
  db.py              база SQLite, схема, транзакции
  auth.py            вход, роли, проверка прав, хеш паролей (bcrypt)
  players.py         игроки и аккаунты
  events.py          события
  attendance.py      явка и сводка
  squads.py          состав на игру
tests/               автотесты
data/                файл базы (создаётся автоматически, в репозиторий не попадает)
```

Правила и проверка прав находятся в `teamplan/`, а не в экранах: права проверяются при каждой операции, а не только скрытием кнопок.

## Безопасность

- Пароли хранятся только в виде хеша с солью (bcrypt), в открытом виде нигде не сохраняются и не выводятся.
- При неверном входе сообщение не говорит, что именно неверно.
- Файл базы и секреты исключены из репозитория через `.gitignore`. Все данные в проекте вымышленные.

## Ограничения

- Демонстрационный режим: приложение запускается на одном компьютере, пользователи входят по очереди. Постоянная работа для всей команды с разных устройств не предусмотрена.
- Игрок не может сменить пароль сам, при утере пароль задаёт организатор. Саморегистрации нет.
- Пароль не длиннее 72 байт (ограничение bcrypt; русская буква занимает 2 байта).
- Внешние уведомления (почта, мессенджеры) не предусмотрены.

## Принятые допущения (уточняются по ТЗ)

- Тип события после создания не меняется. Отменённое событие не редактируется.
- На отменённое событие явку отметить нельзя; состав отменённой игры не меняется.
- Пустой состав опубликовать нельзя; опубликованный состав не может стать пустым. Изменения опубликованного состава видны игрокам сразу.
- Дата события при создании не раньше сегодняшнего дня (проверяется дата, не время).
- Логины не различают регистр (`Igrok1` и `igrok1` считаются одним логином).
- Минимальная длина пароля не задана (в ТЗ нет).
